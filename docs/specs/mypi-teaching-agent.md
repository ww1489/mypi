# Spec: mypi — 从零写一个 PiG 式 Agent（8 步教学）

状态：draft（seam 待确认）
标签：`enhancement` + `ready-for-agent`（待 issue tracker 就绪后应用）

## Problem Statement

学习者想真正掌握"agent 是怎么跑起来的"，但现有参照物 `/data/code/PiG` 是 3251 个非测试 Go 文件的完整移植：四条前端（TUI / print / json / RPC）、扩展宿主、Piglet 打包、42 家 provider、生成代码目录。直接阅读无法建立"最小可运行内核"的心智模型——到处都是细节，看不到主干；而抄写又只会得到能跑但不理解的结果。

真正的痛点有三条：

1. **缺一条从空目录到可运行 agent 的最短路径**。没有任何材料说明"最少需要哪几块、按什么顺序长出来"。
2. **缺客观的"做对了没有"判定**。学习者的实现与 PiG 的差异是隐性的：看上去都能对话，但可能漏掉了工具声明增量、结果顺序确定性、压缩切点合法性这些关键设计。
3. **缺可回放的中间态**。一步到位的"完整 agent 代码"无法展示设计演化——为什么 channel 不够、为什么工具接口要长出 `ExecutionMode`、为什么压缩不能切开 tool call 与 result。

## Solution

在 `/data/code/mypi` 从空目录长出一个 Go agent，模块名 `mypi`，二进制 `mypi`，**目录与 PiG 同名同构**（`ai/` `agent/` `tools/` `session/` `internal/` `cmd/mypi/`），使学习者可以逐层与 PiG 的对应文件并排对照。

整个实现由 8 个里程碑（Step 0–7）组成，每个里程碑是一个**可运行、可测试、可 commit 的中间态**：

1. 骨架 + 脚本化假 provider（离线，无网络）
2. 纯文本对话循环（多轮 REPL）
3. 极简工具接口 + `read` / `bash`，跑通工具回灌闭环
4. 工具接口演化到 PiG 形状：并发执行、源顺序结果、工具声明以 system message 增量下发
5. 真实 provider（`openai-completions` + deepseek，SSE 流式）
6. 事件流升级 + JSONL 会话树（`--resume` / `--fork`）
7. compaction（token 估算、合法切点、`/compact` 与阈值触发）
8. （加餐）最小 TUI：差分渲染 + 单线程事件循环

学习者的角色是写核心逻辑；助手的角色是每步给出设计问题、接口约束、验收测试，并在完成后生成"我的实现 vs PiG"差异清单。教学产物（`AGENTS.md`、`docs/compare/step-NN.md`）与代码同等重要：它们让学习过程可续、可回放、可审计。

## User Stories

1. 作为学习者，我想要一条从空目录到第一个可运行 agent 的最短路径，以便在几小时内看到真实输出，而不是先读完 3251 个文件。
2. 作为学习者，我想要每个 Step 都是一个能 `go run` 的中间态，以便用 `git diff` 精确看到这一步新增了什么能力。
3. 作为学习者，我想要每一步都配一份可执行的验收测试，以便不需要主观判断"我做对了没有"。
4. 作为学习者，我想要验收测试先于实现出现，以便我在动手前先读懂"这一步要求的行为"。
5. 作为学习者，我想要某个 Step 卡住超过两小时后能拿到该步的参考实现，以便单点阻塞不会摧毁整个学习节奏。
6. 作为学习者，我想要每步完成后得到一份与 PiG 的差异清单，以便知道自己漏掉了哪个设计意图、而不是只知道自己能跑。
7. 作为学习者，我想要差异清单引用 PiG 的精确文件与符号，以便我能直接跳进去读原始实现。
8. 作为学习者，我想要 Step 0–3 全程离线可跑，以便在没有密钥、没有网络的环境里也能练习核心循环。
9. 作为学习者，我想要消息类型用 Go 惯用的接口加类型分支，以便学到的是 Go 的写法而不是 TypeScript 的翻译腔。
10. 作为学习者，我想要消息的 JSON 字段名镜像 PiG，以便第 6 步存盘时能与 PiG 的会话格式逐字段对照。
11. 作为学习者，我想要先体验朴素 channel 流式、再升级到有序可多次消费的事件流，以便亲手理解"为什么 channel 不够用"。
12. 作为学习者，我想要工具接口从极简签名逐步演化到完整形状，以便理解每个方法是为了解决什么问题才长出来的。
13. 作为学习者，我想要工具声明以 system message 增量形式下发，以便理解动态工具集在真实协议里如何表达。
14. 作为学习者，我想要并行工具执行的结果按调用源顺序落盘，以便理解"并发执行 + 确定性输出"这对约束。
15. 作为学习者，我想要每次对照都产出一个可提交的文档，以便我的学习轨迹留在仓库里而不是散在聊天记录里。
16. 作为 mypi 用户，我想要用 `mypi "问题"` 单次提问并以管道友好的方式输出，以便把它当普通命令行工具使用。
17. 作为 mypi 用户，我想要交互式多轮对话，以便连续追问而不必重述上下文。
18. 作为 mypi 用户，我想要看到回答的流式增量，以便长回答不必等全部生成完才显示。
19. 作为 mypi 用户，我想要非交互模式下 stdout 只包含回答内容、诊断信息走 stderr，以便能安全地接管道与重定向。
20. 作为 mypi 用户，我想要 `mypi --version` 与 `mypi --help` 不读取用户配置即可工作，以便脚本化调用行为可预期。
21. 作为 mypi 用户，我想要 agent 能读取文件并据此回答，以便我不必手动粘贴代码。

25. 作为 mypi 用户，我想要工具结果与我的调用顺序严格对应，以便我能读懂执行过程。
26. 作为 mypi 用户，我想要单个工具失败被当作工具结果回灌而不是中断整个 run，以便模型能自行纠错。
27. 作为 mypi 用户，我想要 bash 工具带超时、输出截断、不接管 stdin，以便 agent 不会挂死终端。
28. 作为 mypi 用户，我想要工具输出被截断且附带"已截断"提示，以便长输出不会塞爆上下文。
29. 作为 mypi 用户，我想要用真实模型（deepseek）跑通含工具调用的对话，以便验证我的实现对真实协议的兼容性。
30. 作为 mypi 用户，我想要 API key 从环境变量优先、回退到已有 pig 配置读取，以便我不必把密钥写进仓库。
31. 作为 mypi 用户，我想要网络错误、超时、限流时看到明确错误信息，以便我不会误以为 agent 卡死。
32. 作为 mypi 用户，我想要会话自动落盘，以便进程中断后上下文不丢失。
33. 作为 mypi 用户，我想要 `--resume` 恢复上次会话，以便隔天继续同一个任务。
34. 作为 mypi 用户，我想要 `--fork` 从历史某点分叉出新的对话分支，以便尝试不同问法而不污染主线。
35. 作为学习者，我想要会话文件是每行一条 JSON 的追加式树，以便我能用 `jq` 直接观察 agent 的内部状态。
36. 作为 mypi 用户，我想要上下文接近窗口上限时自动压缩，以便长任务不会突然失败。
37. 作为 mypi 用户，我想要手动触发压缩，以便在预感要溢出时主动减负。
38. 作为 mypi 用户，我想要压缩提示里说明"哪些内容被摘要替换"，以便我知道信息损失在哪里。
39. 作为 mypi 用户，我想要压缩绝不切开工具调用与其结果，以便压缩后模型不会看到非法的消息序列。
40. 作为 mypi 用户，我想要一个最小终端 UI：消息块、工具执行状态、可滚动历史，以便阅读体验优于纯文本追加。
41. 作为 mypi 用户，我想要输入框支持多行编辑，以便粘贴多行代码。
42. 作为学习者，我想要 UI 与 agent 事件在同一个主循环上派发、慢活丢后台再 marshaling 回来，以便理解 PiG 为什么用单线程事件循环而非共享内存回调。
43. 作为 CI，我想要 `go vet ./...` 与 `go test ./...` 是唯一门槛，以便仓库不引入额外工具链依赖。
44. 作为 CI，我想要所有测试默认离线且无需密钥，以便 fork 与 PR 都能跑。
45. 作为维护者，我想要 `AGENTS.md` 记录与 PiG 的对应表与每步验收清单，以便新会话能立刻接上上下文。
46. 作为维护者，我想要 Step 6 之前零第三方依赖，以便学习者只需理解标准库。
47. 作为维护者，我想要目录名与 PiG 保持一致，以便对照时零翻译成本。
48. 作为维护者，我想要一个明确的"范围之外"清单，以便学习者不会误以为必须复刻 42 家 provider 才算完成。

## Implementation Decisions

**模块与布局**

- Go 模块名 `mypi`，二进制 `mypi`，入口在 `cmd/mypi`；目录与 PiG 同名：`ai/`、`agent/`、`tools/`、`session/`、`internal/`、`tui/`（仅 Step 7）。
- 命令行参数手写解析，不引入 cobra/pflag；风格对齐 PiG 的手写 `Args` 结构（字段注明来源），使"为什么大项目也手写"成为一个可讨论点。
- Step 0–6 零第三方依赖（仅标准库）；Step 7 允许 `golang.org/x/term`。

**消息模型**

- 消息用 `interface Message` + 具体结构体 + 类型分支，而非 PiG 的手写 sum type（五个指针字段 + `Custom map`）。
- 结构体字段的 JSON tag 镜像 PiG：`role`、`toolCallId`、`toolName`、`stopReason`、`isError` 等，保证 Step 6 的落盘格式可与 PiG 会话文件逐字段对照。
- 消息角色集合：system / user / assistant / toolResult；assistant 的内容是内容块序列（文本块、思考块、工具调用块）。

**流式与事件**

- Step 0–4 使用朴素 `chan Event` 加错误字段的流。
- Step 6（事件流升级）替换为有序、无界缓冲、可多次取结果、懒启动的事件流，并保留一份"channel 为什么不够"的对照笔记：单次消费不可回放、缺背压语义、错误与终止的表达不统一、无法同时供 UI 与落盘消费。
- 事件类型是封闭并集：run 开始/结束、turn 开始/结束、消息开始/增量/结束、工具执行开始/更新/结束。事件是外部可观测行为，UI 与落盘都只消费事件。

**循环**

- 循环分两层：外层处理"还有没有后续消息（steering / follow-up）"，内层处理"是否还有工具调用"。每一轮 = 一次流式响应 + 一批工具 + turn 结束事件。
- 终止条件显式化：正常停止、工具批要求终止、错误停止、达到最大轮数。
- 模型返回"被截断（长度超限）"时，该批工具调用全部失败而不执行——防止在半截参数上做破坏性操作。

**工具**

- Step 2 的接口只有 `Execute(ctx, 原始 JSON 参数) (结果, error)`；Step 3 演化到完整形状：名称、标签、schema、带调用 ID 的执行、增量回调、执行模式（并行/串行）。
- 工具声明不下发为独立请求字段，而是作为 system 消息的增量（新增/移除）随请求发送，镜像 PiG 的 `toolsAdded` / `toolsRemoved` 设计。
- 并行执行：按调用源顺序发出开始与准备，并发执行，完成顺序随意，但回灌的工具结果消息严格按源顺序排列；任一工具声明为串行则整批串行。
- 工具失败成为 `isError` 的工具结果而非中断；工具输出统一截断策略（行数与字节双阈值）+ 截断提示。
- bash 工具：命令超时、输出截断、不接管 stdin、工作目录为启动目录。

**Provider**

- 只实现一种协议：OpenAI 兼容的 `chat/completions` + SSE 流式分帧；不实现 responses API、Anthropic messages、bedrock 等。
- provider 接口形态对齐 PiG：`ID()` + `Stream(ctx, 上下文, 选项)`；上下文是不可变快照，选项含密钥、温度、最大 token 等。
- 密钥解析顺序：环境变量优先，回退读取已存在的 pig 认证配置；密钥永不写入仓库与会话文件。
- faux provider（脚本化响应）在 Step 5 之后保留为测试专用，主路径默认真实 provider，由环境变量或配置切换。

**会话与持久化**

- 会话目录默认 `~/.mypi/sessions/<按项目路径编码的子目录>/`，与 PiG 的目录编码思路一致。
- 会话文件为追加式 JSONL，首行为会话头（版本、id、cwd、时间），其后每行一条带 `id` 与 `parentId` 的条目；`parentId` 构成树，指向更早节点即分叉。
- 条目种类：消息、模型变更、用量、压缩摘要、自定义条目。
- 上下文构建规则：取从当前叶节点回溯到根的活跃分支；压缩摘要条目替换其覆盖的历史消息，但文件中保留原始条目。

**Compaction**

- 触发：估算上下文 token 超过（窗口 − 预留）或 provider 报上下文超限。
- 切点规则：合法切点只落在 user / assistant / 工具执行 / 分支摘要 等消息边界上；**绝不把工具结果与其调用切开**。
- 保留策略：保留最近一段 token 预算，更早部分交模型摘要；摘要作为新的压缩条目落盘并参与后续上下文。
- 分隔符与摘要提示文案属于实现细节，不追求与 PiG 逐字一致。

**TUI（加餐）**

- 组件模型：`Render(宽度) []string` + `Invalidate()`；容器负责差分渲染，只重绘变化的行。
- 单线程派发：agent 事件与键盘输入在同一个主循环上处理，慢操作丢到后台 goroutine 完成后再投递回主循环——不复刻 PiG 的完整终端能力协商、不做 markdown 渲染与语法高亮。

**教学产物**

- 每步一份任务卡：本步要回答的设计问题、接口与目录约束、验收测试、验收命令。
- 每步完成后生成 `docs/compare/step-NN.md`：PiG 对应文件的符号级引用、差异清单、本步实现遗漏的设计意图、以及下一层的前置条件。
- `AGENTS.md` 记录：模块与目录映射、每步验收清单、密钥读取方式（只记录方式，不记录值）、范围之外清单。

## Testing Decisions

**什么算好测试**

- 只测外部可观测行为：命令行输入、标准输出/标准错误、退出码、落盘的会话文件、以及假 provider 录到的请求体。不测内部函数、不测私有字段、不对实现结构做断言。
- 测试对重构免疫：把 channel 换成事件流、把工具接口加宽、把会话存储重构，测试应全部不动。
- 每个 Step 的验收测试在该 Step 之前就写好并能失败（Step 0 除外）；测试名直接表述行为。
- 测试默认离线、无密钥、无网络、无时间依赖（假 provider 脚本化响应 + 固定随机源/时间戳注入）。
- 断言优先落在"契约"而非"文案"：例如"工具结果顺序等于调用顺序"、"压缩后不存在孤立的工具结果"、"会话树中 `parentId` 链可回溯到根"。

**Seam（唯一）**

- 唯一 seam：**`mypi` 进程边界**——测试启动 `mypi` 二进制（或等价的进程级驱动），给参数与环境，断言 stdout/stderr/退出码/会话文件。
- 假 provider 通过环境变量指定的脚本文件注入，同时把每次请求的完整载荷录到文件；"工具声明增量"、"消息序列合法性"这类内部协议行为都通过**读录制文件**断言，而不新增 seam。录制文件是同一 seam 的观测面，不是第二个 seam。
- Step 7 的 TUI 不引入第二个 seam：用管道式伪终端驱动，只断言"关键文本出现过 + 进程正常退出"，不做像素级断言。

**被测模块**

- `cmd/mypi` 的参数解析与模式选择（单次 / 交互 / 恢复 / 分叉）。
- `agent` 的循环可观测行为：多轮、工具批、截断保护、最大轮数、错误停止。
- `tools` 的四个工具：读、写、编辑、bash 的截断、超时、错误回灌。
- `session` 的落盘格式、树结构、恢复与分叉。
- `internal` 的压缩切点选择与 token 估算（通过会话文件与录制请求间接断言）。
- `ai` 的 SSE 分帧与工具调用增量拼接（用固定字节流的服务器替身，仍从 CLI 侧驱动）。

**先例**

- PiG 的脚本化假 provider（`ai/faux.go`）与本设计同源，可作对照阅读。
- PiG 的 parity 场景是黄金样例风格（固定输入 → 固定可观测输出），mypi 采用同样的"录请求 + 断言请求/响应形状"思路，但不做 oracle 逐字节比对。
- PiG 中几乎每个源文件都有对应测试；mypi 不追求那种密度，只覆盖每步验收行为。

## Out of Scope

- 与 Pi 的字节级 parity、oracle 测试、覆盖率账本、差异编号文化（属 PiG 维护目标，非教学目标）。
- 42 家 provider、多种协议（responses / Anthropic messages / bedrock / vertex / mistral）、模型目录生成器。
- 扩展宿主（Go/Rust/Python 子进程 SDK）、MCP 客户端、Piglet 打包、RPC 模式、print/JSON 双模式之外的第三四种前端。
- Piglet / 包分发 / AOT 编译 / 遥测 / durable / chord / codemode / env 远程执行。
- 完整 TUI：markdown 渲染、语法高亮、主题、overlay、多行编辑器的高级按键、Kitty 键盘协议、终端能力协商、alt-screen 切换与 surface 合成。
- 图片输入、粘贴附件、上下文 @ 文件补全、技能（skills）加载、AGENTS.md 上下文注入机制（PiG 有，mypi 不做）。
- Windows 平台承诺、跨平台 shell 支持（仅 bash 与 powershell 二选一中的 bash）。
- 把密钥管理做成一等公民（keyring、OAuth 登录、订阅账号）。

## Further Notes

- **前置条件**：Go 1.27 可用（已安装于 `~/.local/go`）；无需 Node.js 或其他运行时。
- **节奏**：单步 30–90 分钟，单次会话推进 1–2 步；总投入估计 15–25 小时（Step 0–6 主线，Step 7 视余力）。
- **逃生舱**：任一步骤超过两小时未通过验收，允许直接提供该步参考实现，由学习者回读并补一份"我卡在哪"的笔记；该步记为 `step-N-ref`，不视为失败。
- **Step 3 的安全边界**：教学版 bash 工具加最小限制（超时、输出截断、不接管 stdin），与 PiG 的截断策略对齐；不做沙箱、不做权限确认弹窗。
- **对照优先级**：当"贴近 PiG"与"Go 惯用"冲突时，选择 Go 惯用并在差异清单里记录理由；唯一例外是 JSON 字段名与目录命名，必须贴 PiG。
- **命名**：术语沿用 PiG 词汇（agent loop、turn、tool call、tool result、session tree、compaction、event stream、provider、faux），不新造词。
