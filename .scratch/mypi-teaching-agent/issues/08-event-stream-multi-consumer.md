# 08: 事件流升级：多消费者同时工作

**What to build:** 同一轮 run 的事件可以被**同时**消费两次——一次用于终端渲染、一次用于落盘录制——且后到的消费者仍能拿到完整序列。新增 `--record <file>`，把本次 run 的完整事件流写成可回放的文件。终止与错误语义统一为事件（而不是散落在返回值与 channel 关闭里）。

这张票的隐性验收是**前七张票的测试一行不改仍然全绿**：它替换的是内部传输机制，外部行为不能变。

**Blocked by:** 07

**Status:** ready-for-agent

- [ ] 同一次 run 中两个消费者各自收到全部事件，顺序一致且不互相消费掉对方的数据
- [ ] 消费者晚于 run 开始订阅时，仍能拿到从头开始的完整事件序列
- [ ] `--record <file>` 产出的文件可被解析为有序事件序列，且与终端所见一致
- [ ] run 的终止（正常/错误/中止）在事件流中以明确事件表达
- [ ] 前七张票的测试全部保持原样通过
